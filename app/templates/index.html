Edvexa Platform Architecture & Governance Rules

1. Accounting & Mutual-Exclusion Rule

Every single record ingested is deterministically classified into exactly one category:

total_rows = accepted_rows + rejected_rows + duplicate_rows + skipped_rows
  • Accepted: Passed all schema and business validations; inserted into clean tables.
  • Rejected: Failed one or more field-level checks (e.g. missing required field, bad email, unparseable date, negative price).
  • Duplicate: Valid syntax, but the unique business key was seen earlier in the file or exists already in clean records.
  • Skipped: Safe bypass if an entire identical file run is audited according to policy.

2. Idempotency & Repeat Upload Policy

Each uploaded CSV is hashed via SHA-256. If the same file is submitted multiple times:

  • An audit record is created for historical transparency.
  • Existing primary keys in the database are recognized and accounted for as duplicate_rows.
  • No duplicate rows are ever inserted into clean tables.
  • Clean records remain pristine and unmodified.
